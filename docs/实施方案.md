# 用户意见反馈系统（FeedLog-like）实施方案 · 最终版

**版本**：v3.0（完整定稿）　**范围**：反馈（Post）、更新日志（Changelog）两大核心模块。AI 辅助、路线图、邮件通知、全文搜索、版本留存等不在首期范围。


## 一、项目概述

### 1.1 核心功能

| 模块 | 内容 |
|---|---|
| **反馈（Post）** | 看板归属、状态流转、富文本（图片/MP4）、匿名/登录发布、投票、楼中楼评论、作者可关闭 |
| **更新日志（Changelog）** | 富文本（图片/MP4）、草稿/发布；**仅管理员可编辑**；与 Post 状态独立，无联动 |
| **看板（Board）** | 组织容器，粒度的匿名开关与公开性 |
| **身份** | 匿名默认全开 + HS256 JWT 跳转 SSO（FeedLog 兼容）+ 两级角色（user/admin） |
| **存储** | RustFS（S3 兼容）presigned PUT 直传，Caddy 同域反代，支持 MP4 Range 播放 |

### 1.2 关键决策一览

| 决策项 | 结论 |
|---|---|
| 架构 | 前后端分离 + 模块化单体，Repository 层注入 |
| 仓库 | **单仓 monorepo**：`backend/` + `frontend/` + `deploy/` + `docs/` |
| 数据库 | 开发 SQLite，生产 Postgres，`DATABASE_URL` 单变量驱动，无代码分支 |
| SSO | HS256 JWT 跳转，`/api/sso/jwt?token=&return_to=`，失败降级匿名 |
| `return_to` | 仅站内相对路径，非白名单静默回退 `/` |
| 密钥轮换 | `SSO_SECRETS` JSON 数组 + 重启（零停机窗口） |
| 匿名 | 读/投票/发帖/回帖**默认全开**，Board 级可收紧 |
| 角色 | 两级 `user`/`admin`，管理员由 `ADMIN_EMAILS` 环境变量 + 重启维护 |
| 限流 | **无 Redis**，数据库计数表 + UPSERT 固定窗口 |
| 对象存储 | Caddy `/storage/` 反代 RustFS，**path-style 签名**，仅 presigned PUT |
| 视频 | 仅 MP4 上传，单文件 ≤100MB，不转码不分片，原生 `<video>` + Range |
| 富文本 | Tiptap/ProseMirror JSON 为真相源，服务端结构 + 归属校验 |
| 编辑 | **编辑即覆盖，无版本留存** |
| 前端 | Vite 8 + Vue 3.5 + `@tabler/icons-vue`，字体自托管/系统栈，零 Google Fonts |
| 部署 | Docker Compose 单机，GHCR 镜像 + 目标机 `pull && up -d` |
| CI | GitHub Actions，两个独立 workflow + path filter，Postgres service 跑迁移 |


## 二、总体架构

```
                    ┌────────────────────────────────────────────┐
   浏览器 ──HTTPS──▶│  Caddy（frontend 容器，同域统一入口）        │
                    │  /          → Vite 静态产物                 │
                    │  /api/      → backend:8000                  │
                    │  /storage/  → rustfs:9000（保留 URI，path-style）│
                    └──────┬──────────────────────┬───────────────┘
                           │                      │
                    ┌──────▼──────┐        ┌──────▼──────┐
                    │  backend    │───────▶│  rustfs     │  (仅内网可达)
                    │  (FastAPI)  │        │  (S3 API)   │
                    └──────┬──────┘        └─────────────┘
                           │
                    ┌──────▼──────┐
                    │  postgres   │
                    └─────────────┘
```

**核心原则**：

1. **同域部署**：前端、API、对象存储共用 `https://feedback.example.com`。浏览器直传 RustFS 为同源请求，RustFS 侧无需 CORS，后端 CORS 仅放行自身域名。
2. **RustFS 不暴露公网端口**：仅 `backend` 与 Caddy 内网可达，降低攻击面。
3. **后端分层**：`API → Service → Repository → ORM/适配器`，Repository 通过 `Depends()` 注入，SQLite 内存库支撑单测。
4. **前后端成对发布**：同一 commit sha 作为两端镜像 tag。

## 四、后端设计

### 4.1 技术栈

| 组件 | 选型 |
|---|---|
| 语言/框架 | Python 3.12 + FastAPI（全链路 async） |
| ORM | SQLAlchemy 2.x async + `async_sessionmaker` |
| 迁移 | Alembic（唯一 schema 权威，禁 `create_all`） |
| 驱动 | `aiosqlite`（开发）/ `asyncpg`（生产） |
| 对象存储 | boto3 + RustFS，`signature_version="s3v4"`、`addressing_style="path"` |
| JWT | PyJWT（仅 HS256） |
| 配置 | pydantic-settings |

### 4.2 数据模型

| 表 | 关键字段 |
|---|---|
| **Board** | `id`, `slug`(uniq), `name`, `description`, `is_public`, `allow_guest_posting/voting/commenting`(默认 `True`), `created_at` |
| **Post** | `id`(UUID), `board_id`, `title`, `content`(JSON), `excerpt`, `status`(`open/planned/in_progress/completed/closed`), `author_id`(nullable), `anonymous_token`(nullable), `vote_count`, `comment_count`, 时间戳 |
| **Comment** | `id`(UUID), `post_id`, `parent_id`(nullable, 自引用 `ondelete=CASCADE`), `content`, `author_id`/`anonymous_token`, 时间戳 |
| **Vote** | `id`, `post_id`, `user_id`(nullable), `anonymous_token`(nullable), `created_at` |
| **ChangelogEntry** | `id`, `title`, `content`(JSON), `excerpt`, `is_published`, `published_at`(nullable), 时间戳 |
| **User** | `id`, `email`(uniq, 小写), `display_name`, **`role`**（`user`\|`admin`, 默认 `user`）, `sso_provider`, 时间戳 |
| **Upload** | `object_key`(PK), `identity`, `purpose`, `content_type`, `size`, `created_at` |
| **Tag / PostTag** | `tags.name`, `tags.normalized`(uniq, casefold), `is_builtin`；`post_tags(post_id, tag_id)` 多对多 |
| **AuditLog** | `id`, `actor_id`(nullable, SET NULL), `actor_email`(快照), `action`, `target_type`, `target_id`, `detail`(JSON), `ip`, `created_at`；只追加 |
| **RateLimitCounter** | `identity_key`, `action`, `window_start`, `count`；主键 `(identity_key, action, window_start)` |

**索引与约束**：

- Post 列表 keyset 分页：`(board_id, created_at DESC, id DESC)`。
- Vote 唯一性用**两个部分唯一索引**：
  - `UNIQUE(post_id, user_id) WHERE user_id IS NOT NULL`
  - `UNIQUE(post_id, anonymous_token) WHERE anonymous_token IS NOT NULL`
- 评论树按 `post_id` 扁平取出，Service 层组装；**深度上限 3 层**，超出挂到根评论以“回复 @xxx”呈现，避免无限嵌套与 N+1。
- `vote_count` / `comment_count` 在同事务内维护，不依赖触发器（跨库语法差异大）。
- **不建** `PostRevision` / `ChangelogRevision`，编辑即覆盖。

### 4.3 数据库切换

- `DATABASE_URL` 单变量驱动，业务代码无 `if sqlite` 分支。
- 仅引擎创建时按前缀附加 connect args：SQLite 需 `check_same_thread=False`、`PRAGMA journal_mode=WAL`、`busy_timeout=5000`。
- Alembic 类型用 SQLAlchemy 2.x 方言感知：`sa.Uuid()`、`sa.DateTime(timezone=True)`、`sa.JSON`。
- Vote 部分唯一索引用 `op.create_index(..., sqlite_where=..., postgresql_where=...)` 显式渲染。
- 富文本结构校验在应用层，不依赖 DB 约束。
- **生产固定 Postgres**；SQLite 仅开发/测试，不做生产承诺。

### 4.4 SSO：HS256 JWT 跳转（FeedLog 兼容）

**流程**：

```
产品A 已登录 → 后端签发 HS256 JWT（5min）→ 302 到
  https://feedback.example.com/api/sso/jwt?token={jwt}&return_to=/board/xxx
产品A 未登录 → 直接 302 到目标页（不带 token，匿名继续）
反馈系统验证 JWT → JIT 用户 + 角色同步 → 签发本系统会话 → 302 到 return_to
```

**JWT 规格**：

| 项 | 值 |
|---|---|
| 算法 | **仅 HS256** |
| 密钥 | 64 位 hex 字符串，仅存服务端，UTF-8 直接使用**不做解码** |
| `email`（必需） | 含 `@`，trim + 小写 |
| `exp`（必需） | Unix 秒，建议 **300s** |
| `name` | 可选 |
| 其他声明 | 忽略；**不信任 JWT 中的 role 类声明** |

**验证逻辑**：失败（过期/签名错）**不阻断**，降级匿名访问并记 warning；成功则签发本系统 access JWT（15min）+ refresh token（HttpOnly cookie，7d）。SSO token **不落库不写日志**。

**`return_to` 校验**（站内相对路径）：

```python
def validate_return_to(raw: str | None) -> str:
    if not raw: return "/"
    if not raw.startswith("/") or raw.startswith("//") or "\\" in raw:
        return "/"
    p = urlparse(raw)
    if p.scheme or p.netloc:
        return "/"
    return raw
```

校验失败静默回退 `/`，不向攻击者暴露。

**密钥轮换**（环境变量 + 重启）：

1. `SSO_SECRETS='["new","old"]'` → 重启 backend。
2. 通知签发方切到 `new`，等 ≥ 5 分钟。
3. `SSO_SECRETS='["new"]'` → 重启 backend。

### 4.5 角色与管理员

**模型**：`User.role ∈ {"user", "admin"}`，不做细粒度 RBAC。

**管理员产生方式**（SSO JIT 无注册流程，不能靠库表手改）：

```bash
ADMIN_EMAILS="alice@example.com,bob@example.com"
```

- SSO 登录时（JIT 匹配或已有用户）统一执行：`user.role = "admin" if email in ADMIN_EMAILS else "user"` 并写回。
- 增删管理员 = 改环境变量 + 重启 backend；下一次 SSO 登录或 access token 过期后重新走 SSO 生效。
- **角色完全由本系统基于邮箱判定**，不信任签发方 token 中的角色字段。
- `ADMIN_EMAILS` 仅存服务端；邮箱比较前 trim + 小写。

**权限依赖**：

```python
async def require_admin(identity = Depends(get_current_identity)) -> User:
    if not isinstance(identity, AuthenticatedUser) or identity.user.role != "admin":
        raise AppException(403, code="ADMIN_REQUIRED")
    return identity.user
```

### 4.6 匿名身份与合并

- 首次匿名写操作时服务端签发 `HttpOnly; SameSite=Lax` 签名 cookie（随机 token），用于会话内去重与登录后合并。**不用 IP/UA 哈希**（IP 会变、不可撤销）。
- SSO 登录时若同时携带匿名 cookie，在**同一事务**内执行 `merge_anonymous_identity()`：
  1. `Post.author_id` 由 NULL → `user.id`，清空 `anonymous_token`；
  2. `Vote` 匿名记录尝试转 `user_id`；若该用户已有登录票则删除匿名票；
  3. 清除匿名 cookie。
- 合并失败不阻断登录，记日志，下次写操作重试。

### 4.7 限流：数据库计数表（无 Redis）

固定窗口 + UPSERT，SQLite 与 Postgres 共用：

```python
insert(RateLimitCounter).values(
    identity_key=key, action=action, window_start=window, count=1
).on_conflict_do_update(
    index_elements=["identity_key", "action", "window_start"],
    set_={"count": RateLimitCounter.count + 1},
).returning(RateLimitCounter.count)
```

| action | 窗口 | 上限 |
|---|---|---|
| vote | 1 分钟 | 20 |
| post | 10 分钟 | 5 |
| comment | 1 分钟 | 10 |

**注意**：

- SQLite 需 `PRAGMA journal_mode=WAL` + `busy_timeout=5000`，否则多 worker 写计数表 `database is locked`。
- 每小时后台任务清理 `window_start < now - 1h`，防表膨胀（FastAPI `lifespan` 内 `asyncio` 循环）。
- 固定窗口边界可能双倍突发，反馈场景可接受；后续按需升级滑动窗口。

### 4.8 对象存储：presigned PUT + Caddy 反代

**签名 client**（与浏览器实际请求完全一致）：

```python
signer = boto3.client(
    "s3",
    endpoint_url="https://feedback.example.com",       # 公网同域
    aws_access_key_id=..., aws_secret_access_key=...,
    config=Config(signature_version="s3v4",
                  s3={"addressing_style": "path"}),
    region_name="us-east-1",
)
# URL: https://feedback.example.com/storage/uploads/<key>?X-Amz-...
```

**内部 client**（后端删除/校验对象）：`endpoint_url="http://rustfs:9000"`，同样 path-style，不经 Caddy。

**bucket 名 = `storage`**，与 Caddy 前缀一致，保证 canonical URI 对齐。

**上传流程**：

1. `POST /api/v1/uploads/presign`（filename, content_type, purpose, size）
2. 后端校验 purpose / content-type / size 白名单 → 生成 key → 签名 → 写 `Upload` 表（归属、`content_type`、`size`）
3. 前端 `PUT` 直传，**Content-Type 必须与 presign 声明一致**（参与 SigV4 签名）
4. 前端将 **object key**（非完整 URL）写入 Tiptap `src`，渲染时拼 `/storage/`

**约束**：

- **仅 presigned PUT，不用 presigned POST**（RustFS POST 策略条件有绕过缺陷）。
- 单文件上限 100MB（与 Caddy `request_body max_size` 及 `UPLOAD_MAX_BYTES` 对齐），首期不做分片。
- RustFS 凭证首次启动前设定，禁用默认 `rustfsadmin`。
- **未引用对象清理**：presign 写 `uploads` 归属记录，清理任务按 `UPLOAD_CLEANUP_GRACE_HOURS`
  扫描反馈 / 更新日志 JSON，删除超期未引用对象；只处理有 presign 记录的 key，避免误删手工文件。
  支持 CLI（`scripts.cleanup_uploads`）与管理员接口，执行结果写入审计日志。

### 4.9 视频：仅 MP4 上传

**范围与限制**：

- 仅 `video/mp4`；不支持 MOV/AVI/WebM，避免浏览器兼容与转码问题。
- 单文件 ≤100MB（手机拍摄约 1–2 分钟）。
- **不做服务端转码、不做缩略图生成**；播放依赖原生 `<video>`，`preload="metadata"` 加载首帧。
- 不做分片，超限直接拒绝并提示压缩。

**上传与校验**：

- `purpose ∈ {"post_video", "changelog_video"}`，`content_type` 严格等于 `video/mp4`，`size ≤ UPLOAD_MAX_BYTES`。
- key 由服务端决定：`uploads/{uuid}.mp4`（**不信任客户端 filename 后缀**）。
- `Upload` 记录 `content_type`、`size` 供富文本保存时校验。

**Tiptap 节点**：

```json
{ "type": "video", "attrs": { "src": "uploads/<uuid>.mp4", "poster": null } }
```

- `src` 存 object key，渲染拼 `/storage/`。
- 服务端富文本校验：`video.src` 必须匹配 `Upload` 表中**当前身份**、视频 purpose、`content_type=video/mp4` 的记录，否则拒绝保存（防伪造外链/盗用 key）。
- 前端渲染：`<video :src="storageUrl(attrs.src)" controls preload="metadata" playsinline>`。

### 4.10 富文本服务端处理

- 真相源：Tiptap/ProseMirror **JSON**（非 HTML），前端白名单节点渲染，规避 XSS。
- Pydantic 校验：
  - 顶层 `type == "doc"`；
  - 递归限制**最大深度与节点总数**；
  - `image`/`video` 节点 `src` 必须匹配 `Upload` 表中**当前身份**的 object key，且 `purpose` 与媒体类型一致。
- 保存时抽取纯文本到 `excerpt`，列表与搜索不解析大 JSON。

### 4.11 Post 状态机与编辑规则

**状态集合**：`open / planned / in_progress / completed / closed`

**状态流转权限**：

| 当前状态 | 管理员可转为 | 作者可转为 |
|---|---|---|
| `open` | 任意 | `closed` |
| `planned` | 任意 | `closed` |
| `in_progress` | 任意 | `closed` |
| `completed` | 任意 | `closed` |
| `closed` | 任意（含重开） | ❌ |

**规则定稿**：

- **管理员**：任意状态互转，包括把 `closed` 重开为 `open`。
- **作者**：仅允许**单向关闭**——任意非 `closed` → `closed`；关闭后不能自行重开。
- **匿名 Post**（`author_id IS NULL`）：**没有作者身份**，不能自行关闭，仅管理员可关闭。匿名 cookie 不作为授权依据（可清除、不可跨设备）。
- 状态变更写 `Post.status` 与 `updated_at`；**不记录状态变更历史**。

**端点**：

```
PATCH /api/v1/posts/{post_id}/status
Body: { "status": "closed" }
```

```python
def change_status(post, actor, target):
    if actor.is_admin:
        post.status = target
    elif actor.is_authenticated and post.author_id == actor.user.id:
        if target != "closed" or post.status == "closed":
            raise AppException(403, code="STATUS_FORBIDDEN")
        post.status = "closed"
    else:
        raise AppException(403, code="STATUS_FORBIDDEN")
```

**编辑权限（编辑即覆盖，无版本）**：

| 状态 | 作者可编辑 | 管理员可编辑 |
|---|---|---|
| 非 `closed` | ✅ | ✅ |
| `closed` | ❌ | ✅ |

- 匿名 Post 无作者，不可编辑，仅管理员可编辑。
- 编辑直接覆盖 `title` / `content` / `excerpt`，更新 `updated_at`；不记修订历史。
- **已关闭 Post 冻结**：不可编辑、不可新投票、不可新评论；已有数据保留。管理员重开后恢复。

### 4.12 Changelog：仅管理员可编辑

**权限矩阵**：

| 操作 | 匿名 | 登录用户 | 管理员 |
|---|---|---|---|
| 浏览已发布 | ✅ | ✅ | ✅ |
| 浏览草稿 | ❌ | ❌ | ✅ |
| 创建/编辑/发布/删除 | ❌ | ❌ | ✅ |

**草稿与发布语义**：

- 创建时 `is_published=False`、`published_at=NULL`，仅管理员可见。
- `POST /api/v1/changelogs/{id}/publish` 设 `is_published=True`、`published_at=now()`；`unpublish` 反向，**保留 `published_at`**（供审计），用 `is_published` 控制可见性。
- 列表查询：非管理员强制 `is_published=True`；管理员可选 `?include_drafts=true`。
- 编辑即覆盖，无版本历史。

**变更**：Changelog 的**全部写端点**挂 `require_admin`。


## 五、前端设计

### 5.1 工程与依赖

- `pnpm create vite@latest --template vue-ts`（Vite 8 / Rolldown）。
- Vue 3.5 `<script setup>` + TypeScript。
- 图标 `@tabler/icons-vue`；字体**系统栈或 `@fontsource` 自托管**，禁止任何 `fonts.googleapis.com` 请求。
- Feature-First 结构；Pinia 仅存 auth、当前用户角色、board 配置等全局状态。

### 5.2 编辑器（Tiptap）

- `@tiptap/vue-3`：无头、UI 可控、与 `@tabler/icons-vue` 自然配合。
- 扩展：`image`、自定义 `video` 节点。
- 图片/视频上传：编辑器扩展调用 `useUpload` → `presign` → `PUT` → 回填 key。
- 不使用 wangEditor（Vue3+TS 集成弱）/ CKEditor5（体量与定制成本高）。

### 5.3 评论楼中楼

- 后端返回**扁平列表 + `parent_id`**；前端 `useCommentTree` 一次性构建 `Map<id, Node>`。
- 递归组件 `CommentNode.vue` 仅展开时渲染子节点（`v-if="expanded"`）。
- 超过 3 层以“回复 @xxx”平铺卡片呈现。
- `closed` 状态 Post 隐藏评论输入框。

### 5.4 权限相关 UI

- **管理员路由守卫**：`meta.requiresAdmin`，非管理员访问返回 **404**（不返回 403，避免暴露管理入口）。
- **状态选择器**：管理员渲染完整下拉；作者在非 `closed` 时见“关闭反馈”按钮（二次确认），`closed` 后按钮消失；匿名访客不显示任何状态操作。
- **Changelog 入口**：“新建/编辑”按钮仅管理员可见。
- 已关闭 Post 隐藏编辑入口与投票/评论控件。

### 5.5 数据获取

- 首期不引 TanStack Query；页面级 `setup` 直接调 `api/` 模块，`ref`/`shallowRef` 管理加载态。
- 投票**乐观更新**：立即改 UI 计数，失败回滚。


## 六、API 设计要点

- 前缀 `/api/v1`。
- 认证依赖 `get_current_identity()` 返回 `AuthenticatedUser | AnonymousIdentity | None`；`require_admin` 叠加角色校验。
- 分页：**keyset** `(created_at, id)` 游标，非 offset。
- 错误：统一 `{detail, code}`，自定义 `AppException` + handler；状态/权限错误携带 `STATUS_FORBIDDEN`、`ADMIN_REQUIRED` 等业务码供前端提示。
- 投票计数在同事务维护，不依赖触发器。
- 关键端点：
  - `PATCH /posts/{id}/status`
  - `POST /changelogs/{id}/publish`、`POST /changelogs/{id}/unpublish`
  - `GET /changelogs?include_drafts=true`（仅管理员生效）


## 七、部署：Docker Compose + Caddy

### 7.1 Compose 拓扑

实际文件见 `deploy/docker-compose.yml`：四个服务，只有 Caddy（frontend）暴露 80/443，
其余服务仅内网可达。

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment: { POSTGRES_DB: feedback, POSTGRES_USER: feedback, POSTGRES_PASSWORD: ${POSTGRES_PASSWORD} }
    volumes: [postgres-data:/var/lib/postgresql/data]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U feedback"], interval: 10s, retries: 10 }

  rustfs:
    image: rustfs/rustfs:latest
    command: ["/data"]
    environment:
      RUSTFS_ADDRESS: ":9000"
      RUSTFS_ACCESS_KEY: ${RUSTFS_ACCESS_KEY}
      RUSTFS_SECRET_KEY: ${RUSTFS_SECRET_KEY}
    volumes: [rustfs-data:/data]
    # 不暴露端口，仅内网；bucket 由一次性 bootstrap 任务创建

  backend:
    build: ../backend
    env_file: .env
    environment:
      DATABASE_URL: postgresql+asyncpg://feedback:${POSTGRES_PASSWORD}@postgres:5432/feedback
    depends_on:
      postgres: { condition: service_healthy }
      rustfs: { condition: service_started }
    # CMD：alembic upgrade head && uvicorn ... --workers 2
    restart: unless-stopped

  frontend:
    build: ../frontend          # 多阶段：Vite build + Caddy
    environment:
      SITE_ADDRESS: ${SITE_ADDRESS}
      ACME_EMAIL: ${ACME_EMAIL}
    ports: ["80:80", "443:443", "443:443/udp"]
    volumes: [caddy-data:/data, caddy-config:/config]
    depends_on:
      backend: { condition: service_healthy }
    restart: unless-stopped

volumes: { postgres-data: {}, rustfs-data: {}, caddy-data: {}, caddy-config: {} }
```

**要点**：

- `backend` / `frontend` 同时声明 `image` 与 `build`：默认在目标机构建；设置
  `BACKEND_IMAGE` / `FRONTEND_IMAGE` 后可改为 GHCR 拉取。
- `SITE_ADDRESS` 填域名时 Caddy 自动申请 HTTPS；本地无域名可填 `:80`。
- `--workers 2`：SQLite 写锁明显，Postgres 场景 2 worker 足够。
- 迁移内联启动首期可接受；多副本时拆独立一次性任务
  `docker compose run --rm backend alembic upgrade head`。
- RustFS bucket 首次部署执行
  `docker compose run --rm backend python -m scripts.bootstrap_storage`。
- `restart: unless-stopped` 兜底单机可用性。

### 7.2 Caddy 关键配置

```caddyfile
{$SITE_ADDRESS:localhost} {
    encode zstd gzip

    request_body {
        max_size 100MB
    }

    handle /api/* {
        reverse_proxy backend:8000
    }

    handle /storage/* {
        reverse_proxy rustfs:9000
    }

    handle {
        root * /srv
        try_files {path} /index.html
        file_server
    }
}
```

**SigV4 一致性是 P0 必须一次做对的地方**：

| 环节 | 必须 |
|---|---|
| bucket 名 | `storage`，与反代前缀一致 |
| Caddy `handle /storage/*` | **不重写路径**，否则 canonical URI 不匹配 → 403 |
| Host | Caddy 默认保留原始 Host |
| boto3 config | `signature_version="s3v4"` + `addressing_style="path"` + 固定 `region_name` |
| 前端 PUT 头 | `Content-Type` 与 presign 声明一致 |

**视频播放**：依赖 Range 请求（206），RustFS 支持；Caddy `reverse_proxy` 流式转发，
无需额外的响应缓冲关闭配置。`request_body max_size 100MB` 与
`UPLOAD_MAX_BYTES` 对齐。

## 八、CI/CD：GitHub Actions

### 8.1 两个独立 workflow（path filter）

**backend.yml**：

```yaml
on:
  push:
    branches: [main]
    tags: ["v*"]
    paths: ["backend/**","deploy/**",".github/workflows/backend.yml"]
  pull_request:
    paths: ["backend/**","deploy/**",".github/workflows/backend.yml"]

jobs:
  test:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: backend } }
    services:
      postgres:
        image: postgres:16-alpine
        env: { POSTGRES_PASSWORD: test, POSTGRES_DB: test }
        options: >-
          --health-cmd "pg_isready" --health-interval 5s --health-retries 10
    steps:
      - checkout
      - uses: astral-sh/setup-uv@v6
      - run: uv sync --frozen
      - run: alembic upgrade head      # 对 Postgres 跑完整迁移链
        env: { DATABASE_URL: "postgresql+asyncpg://postgres:test@localhost/test" }
      - run: pytest                    # 另跑一套 SQLite 内存库用例
      - run: docker compose config --quiet   # deploy/ 下校验 Compose
  image:
    needs: test
    steps:
      - uses: docker/metadata-action@v6
        id: meta
        with:
          images: ghcr.io/org/feedback-backend
          tags: |
            type=sha,format=long
            type=semver,pattern={{version}}
            type=semver,pattern={{major}}.{{minor}}
            type=raw,value=latest,enable=${{ github.ref == 'refs/heads/main' }}
      - uses: docker/build-push-action@v7
        with:
          context: backend
          file: backend/Dockerfile
          tags: ${{ steps.meta.outputs.tags }}
          push: ${{ github.ref == 'refs/heads/main' || startsWith(github.ref, 'refs/tags/v') }}
```

**frontend.yml**：`paths: ["frontend/**", ...]`，`working-directory: frontend`，`pnpm install --frozen-lockfile && pnpm build`，使用同一套 metadata 规则推 `ghcr.io/org/feedback-frontend`。

### 8.2 必测用例（v3.0 新增）

- 非管理员调用 Changelog 写端点 → 403 `ADMIN_REQUIRED`。
- 作者 `closed` → 不可自行重开；管理员可重开。
- 匿名 Post 不能自行关闭。
- 已关闭 Post 新评论/新投票/编辑 → 拒绝。
- `video` 节点 `src` 伪造或盗用他人 key → 保存被拒。
- `content_type != video/mp4` 的 presign 请求 → 拒绝。
- 恶意 `return_to`（`//evil.com`、`https://evil.com`、`/\evil.com`）→ 回退 `/`。

### 8.3 原则

- **两端共用 `sha-${GITHUB_SHA}` / semver tag**：`latest` 仅 main 推，`v1.0.0` 生成 `1.0.0`、`1.0`；保证成对发布且可回滚。
- 迁移链**必须在 Postgres service 上验证**（UUID / JSON / 部分唯一索引方言差异）；SQLite pytest 保开发路径不回归。
- **RustFS 不在 CI 启动**。S3 通过 `StorageBackend` Protocol 抽象，测试用 `moto` mock。
- **CI 不部署**。产物推 GHCR；目标机 `docker compose pull && docker compose up -d`；回滚改 `TAG` 重启。

## 十一、风险与注意事项

1. **SigV4 一致性是 P0 必须一次做对的**：bucket=`storage`、Caddy `handle /storage/*` 不重写路径、path-style、固定 region、Content-Type 一致。任一错位都在 P2 直传时表现为 403，返工成本高。
2. **单机 Compose 的可用性边界**：backend 崩溃时 Caddy 502，靠 `restart: unless-stopped` 兜底。多副本 + 负载均衡留后续（DB 计数限流表本身已支持多实例共享，无需改架构）。
3. **SQLite 仅开发/测试**：匿名投票并发与限流写竞争在 SQLite 下明显劣化，不做生产承诺。
4. **固定窗口边界突发**：可接受；若被利用再升级滑动窗口。
5. **富文本服务端校验**是落库前唯一防线，P2 必须实现（深度/节点数上限、`image`/`video` 的 `src` 归属与 `content_type` 校验）。
6. **视频存储成本**：唯一显著增长 RustFS 磁盘的数据。`docs/` 注明“100MB × 数量”容量估算，运维侧建议磁盘告警；未引用上传对象由每日清理任务回收，但仍不做上传配额与转码。
7. **`ADMIN_EMAILS` 是唯一的管理员授予路径**：改环境变量 + 重启生效，需在 `docs/sso.md` 明确写入运维 SOP，避免误删导致无人可管理。
8. **`.gitignore` 首次 commit 前就位**，事后清理 `node_modules`/依赖历史成本高。
9. **Alembic cwd**：`alembic upgrade head` 须在 `backend/` 执行，镜像内 `/app/alembic.ini` 必须存在。
10. **已关闭 Post 的冻结语义**：不可编辑、不可新投票、不可新评论；管理员重开恢复。前端需隐藏相应控件，后端需在写入 Service 层做二次校验（不能只靠前端）。

**已确认并落地的事项**：更新日志仅管理员可编辑；Post 状态管理员任意改、作者仅可单向关闭；视频支持 MP4 上传；不做版本留存。方案至此可进入 P0 开工。后续若需扩展（视频封面、上传配额、多副本），均可在现有架构上增量演进，不涉及结构性返工；标签筛选、审计日志与对象清理已落地。
